# Календарь развития и здоровья ребёнка

Кроссплатформенное приложение для комплексного мониторинга физического
и психоэмоционального развития ребёнка: дневник событий, медицинская карта,
результаты анализов, графики роста и планировщик прививок.

**Автор:** Ивашикин Николай

Рабочее название пакета — `child_health_tracker`. Целевая аудитория — родители
и опекуны детей от 0 до 18 лет.

## Статус

Этап 3 — приложение работает на Firebase: авторизация по email и паролю,
данные в Cloud Firestore с офлайн-кэшем.

| Платформа | Состояние |
|---|---|
| Web | собирается, проверено |
| Android | не подключена, добавляется `flutter create --platforms=android .` |
| iOS | требует macOS с Xcode, на Windows недоступна |

Что уже работает:

- **помощник**: офлайн-база знаний с поиском и проверка тревожных признаков
- авторизация: вход, регистрация, восстановление пароля, выход
- профили детей: создание, выбор, удаление с каскадной очисткой записей
- календарь прививок формируется автоматически при создании профиля
- дневник: лента событий, фильтр по типу, добавление вех, измерений и болезней
- антропометрия: графики роста и веса поверх перцентильных кривых ВОЗ,
  z-оценка и вердикт по последнему измерению
- заболеваемость: статистика, подсчёт эпизодов, календарная тепловая карта
- медкарта: диагнозы, назначения, таблицы анализов с подсветкой отклонений
- планировщик: календарь прививок из национального календаря, лекарства, визиты
- дашборд: виджеты можно скрывать и переставлять перетаскиванием

Чего пока нет: загрузки фото и сканов, push-уведомлений, генерации
PDF-отчётов и ручного ввода медицинских записей.

## Firebase

Проект: `child-health-tracker-7aad1`. Конфигурация лежит в
`lib/firebase/firebase_options.dart` — она написана вручную, потому что
`flutterfire configure` требует интерактивного входа в Google. Значения в ней
не секретны: их получает любой клиент веб-приложения, а доступ ограничивают
правила в `firestore.rules`.

Развёртывание требует однократного `firebase login`:

```bash
firebase login
firebase deploy --only firestore:rules,firestore:indexes
flutter build web --release
firebase deploy --only hosting
```

Правила реализуют изоляцию из п. 3.2 ТЗ: каждый документ несёт `parent_uid`,
и любое чтение или запись сверяет его с `request.auth.uid`. Всё, что не описано
явно, запрещено.

Отступление от схемы раздела 4 ТЗ: `parent_uid` продублирован во все коллекции,
а не только в `children`. Без этого правило безопасности вынуждено делать `get()`
на профиль ребёнка при каждом чтении документа — лишняя тарифицируемая операция
и заметно более хрупкое правило. Поле пишет репозиторий, UI о нём не знает.

### Нормы ВОЗ

Таблицы LMS покрывают каждый месяц от 0 до 60 для обоих полов, вес-к-возрасту
и рост-к-возрасту. Файл `lib/core/growth/who_tables.dart` **сгенерирован**
скриптом `tool/generate_who_tables.py` из опубликованного набора данных и
руками не правится:

```bash
python tool/generate_who_tables.py
```

Скрипт проверяет полноту диапазона и сверяется с контрольным значением, поэтому
испорченные данные не попадут в сборку молча. Ранее таблица была записана по
памяти: медианы оказались верны, а коэффициенты L и S — нет, и это смещало
каждую z-оценку.

Старше 60 месяцев оценка **не выдаётся вовсе**: экстраполяция означала бы
сравнение школьника с нормами для малыша.

## Помощник для родителей

Регион — **Казахстан**. Календарь прививок соответствует Постановлению
Правительства РК № 612 от 24 сентября 2020 года.

Помощник состоит из двух слоёв, и оба работают **офлайн и без ИИ**:

**База знаний** (`lib/knowledge/content/`) — статьи жёсткого формата. Каждая
обязана содержать «что делать сейчас», «когда к врачу» и список источников;
это проверяется тестами, а не соглашением. Поиск учитывает разговорные
синонимы: запрос «сопли» находит статью «Насморк».

**Триаж тревожных признаков** (`lib/knowledge/triage.dart`) — детерминированные
правила по NICE NG143 и ВОЗ IMCI. Языковой модели здесь нет и не будет:
на вопрос «вызывать ли скорую двухмесячному» недопустим ответ, который
обычно правильный. Каждое правило покрыто тестом, результат воспроизводим.

Любой исход, включая «наблюдать дома», заканчивается отсылкой к врачу —
это тоже проверяется тестом.

> **Контент требует проверки педиатром.** Материалы составлены по
> рекомендациям ВОЗ, NICE, AAP и NHS, но перед реальным использованием должны
> быть выверены практикующим врачом. Дозировки лекарств проверяются в первую
> очередь.

## Стек

- **Flutter 3.44.8** / Dart 3.12.2 — единая кодовая база
- **Firebase** — Auth, Cloud Firestore, Storage, Cloud Messaging, Hosting
- **Riverpod** или **Bloc** — управление состоянием
- [`fl_chart`](https://pub.dev/packages/fl_chart) — графики антропометрии
- [`pdf`](https://pub.dev/packages/pdf) — генерация медицинских отчётов

## Запуск

Требуется установленный Flutter SDK.

```bash
flutter pub get
flutter run -d chrome          # отладка в браузере
flutter build web --release    # сборка в build/web
```

## Планируемая функциональность

1. **Авторизация и профили** — вход через Firebase Auth, несколько детей в одной учётной записи
2. **Календарь развития** — вехи, ежедневные записи, теги, фотографии
3. **Антропометрия** — рост, вес, окружности; графики с процентильными сетками ВОЗ
4. **Мониторинг заболеваемости** — календарь болезней, статистика, тепловая карта
5. **Медицинский модуль** — анализы, сканы бланков, назначения, сводные PDF-отчёты
6. **Планировщик** — календарь прививок, приём лекарств, визиты к врачу, push-напоминания
7. **Редактируемый дашборд** — настраиваемые виджеты на главном экране

## Структура

```
lib/
  models/       сущности по разделу 4 ТЗ, сериализация под Firestore
  data/         интерфейсы репозиториев и in-memory реализация
  core/
    growth/     перцентили ВОЗ: LMS, z-оценка, вердикт
    vaccination/национальный календарь прививок
    router/     маршруты и список разделов навигации
    theme/      тема оформления
  features/     экраны по модулям ТЗ
  providers.dart  Riverpod-провайдеры, единая точка подмены на Firestore
web/            точка входа веб-версии, PWA-манифест, иконки
test/           тесты
docs/           техническое задание (не версионируется)
```

Переход на Firebase не затрагивает виджеты: достаточно реализовать четыре
интерфейса из `lib/data/repositories.dart` поверх Firestore и подменить
провайдеры в `lib/providers.dart`.

Техническое задание содержит персональные данные и намеренно исключено
из репозитория через `.gitignore` — оно хранится локально.
